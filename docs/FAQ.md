# 常见问题

## CodeGate Leader 是另一个 Coding Agent 吗？

不是。它负责在 Agent 上层管理任务事实、架构、计划、交接和证据。真正修改业务代码的仍是 Codex、Claude Code 或其他 Coding Agent。

## 不配置模型还能用吗？

可以。资料解析、确定性工作流、动态计划、工件存储、工作区观察、CLI 和证据检查均可本地运行。需要开放式解释或语义 Review 时再配置模型。

## 支持哪些模型？

当前 Leader 客户端支持配置 Base URL、模型名和 API Key，适合兼容 OpenAI Chat Completions 请求格式的服务。执行 Agent 与 Leader 模型彼此独立。

## 为什么不能直接让 CodeGate 自动写完项目？

产品刻意保留用户批准边界。CodeGate 的价值是减少盲目执行和错误验收，而不是隐藏所有决策。如果需要更高自动化，可以让 Coding Agent 执行当前 Prompt，但仍建议保留阶段确认和独立验证。

## Agent 明明说完成了，为什么 Review 不通过？

Agent 声明只是低强度证据。Review 还会检查真实文件变化、交接范围、输出工件、需求映射和 CodeGate 自运行验证结果。旧修改、未报告文件和无法复现的日志不会自动计入本轮验收。

## 为什么竞赛模式一定要选择具体赛题？

同一指南可能包含多个完全不同的题型。根据文件名、目录名或全文关键词猜题会产生错误架构和计划。新版要求用户从解析候选中明确选择，并检查对应基础要求和评分项。

## 支持 Linux 和 macOS 吗？

领域核心和 CLI 使用 Node.js/TypeScript，但当前 Desktop 和打包验证主要面向 Windows。本机 Agent 启动、安全存储和安装程序仍需跨平台适配与测试。

## `.codegate/` 应该提交到业务项目 Git 吗？

取决于团队策略。其中不应包含 API Key，但会包含任务、计划、报告和本地路径等项目元数据。个人项目可先忽略；团队希望共享工程决策时，可以审查后选择性提交。CodeGate Leader 自身仓库默认忽略它。

## Windows 为什么提示未知发行商？

当前 Alpha 安装包没有正式代码签名证书。建议开发者从源码运行或自行构建。正式对外发行前必须配置发行商身份、代码签名、法律文本、更新服务和授权服务。

## 如何提交有效 Bug？

使用仓库 Bug Report 模板，填写版本、操作系统、项目阶段、复现步骤和预期/实际结果。优先附上去除敏感信息的诊断导出，不要上传 API Key、许可证 Token、私有源码或完整用户目录。

## 这和普通项目管理工具有什么不同？

普通工具记录人类任务；CodeGate 的工件直接约束 Agent Prompt，并将执行报告、工作区基线和验证证据映射回需求与验收标准。它关注的是 AI 执行链的可控性和可信度。
